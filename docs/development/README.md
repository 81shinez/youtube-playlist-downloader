## 변경 작업 순서

1. 개발 환경을 준비하고 변경할 모듈의 역할을 확인합니다.
2. 동작을 바꿀 때 해당 계층의 테스트를 추가하거나 수정합니다.
3. 관련 테스트를 실행하고, 공통 작업 처리나 프로세스 계약을 바꿨다면 전체 테스트를 실행합니다.
4. 패키징을 바꿨다면 대상 운영체제에서 빌드하고 산출물을 검증합니다.
5. 사용자 동작이 바뀌면 프로젝트 README를, 내부 계약이 바뀌면 해당 개발 문서를 갱신합니다.
